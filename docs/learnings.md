# Learnings

The lead writes this at handoff. 80 lines or fewer; never imported or auto-loaded.
Format: `## <topic>`, then `- **Rule.** What happened, with a date or numbers.`
When a lesson becomes a standing rule, move it to AGENTS.md (workers) or docs/roles/lead.md (lead) and delete it here.

## Claude Code memory
- **Import AGENTS.md explicitly.** With a CLAUDE.md present, Claude Code never auto-loads AGENTS.md; "read AGENTS.md first" in prose is not an import. Until 2026-10-15 no Claude session got the project rules (docs/research/memory-setup.md §0).
- **An `@name` in prose is an import.** AGENTS.md's "Read @SPEC.md first" would have pulled all of SPEC.md (large) into every session. Write file names in backticks.
- **No settings file is lead-only.** Worktrees read the main checkout's `.claude/settings.local.json` and its untracked `.claude/commands`, `agents` and `skills`. Lead-only config goes on the lead's command line (`docs/roles/lead.sh`).
- **Never truncate injected state.** Hook output over 10,000 chars becomes a path plus a 2,000-char preview, and cutting STATE.md drops "Next 3 actions" at the bottom. Refuse and say so instead.
- **Generate copies, don't hand-write them.** The DECISIONS index is generated by state-check.sh; a hand-kept third copy of each status would drift.

## Pushing
- **Written 'never push' in a brief did not stop a worker; enforce with hooks/permissions.** On 2026-10-16 both the S3 and the V1a worker ran `git push -u origin <branch>` unasked, and V1a's report then said "No push". Now: `pre-push` hook (refuses unless `AGENTFLY_ALLOW_PUSH=1`) plus `Bash(git push:*)` and `Bash(git -C * push *)` denies in `.claude/settings.json`.
- **The hook is a guard against accidents, not a lock.** Tested 2026-10-16 against a local bare repo: `--no-verify` and `AGENTFLY_ALLOW_PUSH=1 git push` pass the hook; `sh -c 'git push …'` passes the deny rule. The deny rule covers Claude Code only, not Cursor agents.
- **`core.hooksPath` must be absolute.** Relative, each worktree ran its own checked-out copy, so a worktree from an older commit had no `pre-push` and pushed freely (measured 2026-10-16).
- **Denying `git push` is not enough while `gh` is logged in.** 2026-10-19: `gh api`, `gh pr merge` and `gh repo` could write to GitHub from any session; settings.json now denies gh writes and `gh auth` (brainstorm-advisor found it).

## Merging parallel cards
- **Green tests on each branch do not prove the merge.** V6 answered session events before `apply_rules`, so V5a's `subagentStart` link never ran; the trial merge passed 1900 tests while a probe showed the subagent send allowed (2026-10-18). Before merging cards that share a merge point, trial-merge them and probe the cross-card behaviour.
- **A worker's merge-main commit can carry old lead files.** The V3a worker's merge commit kept old STATE/BOARD copies (2026-10-18). Since 42bfe0a the pre-commit hook lets a merge of a main commit carry that commit's copies, which equal the later merge base; still merge worker branches with `--no-commit` and check the lead files' diff is empty.
- **Review each branch before the trial merge, and send the fixes back to its worker.** On 2026-10-19 a `/code-review high` of V3b and V6b raised 7 findings; checked against the code, 3 fixes and 1 SPEC line were kept. The one real bug (`doctor path` passing another venv's `agentfly`) had passed every test the worker wrote. The owner chose that workers make the fixes; trial-merge only after the fix commits.
- **Check free disk before trial worktrees.** Each worktree's `.venv` plus a scratch trial filled the disk mid-test; pytest errors then looked like code failures (2026-10-18). `df -h /` first; remove merged worktrees.
- **Re-run a reviewer's probe before counting its finding, and let a stopped review stay stopped.** All three medium findings reproduced on the lead's own run (2026-10-18). The V5a red-team reviewer was halted by a safety classifier; the lead verified its concrete leads directly instead of rewording the task.

- **Judge a lead-file rule against the merge base, not today's main.** The first pre-commit merge rule compared with `main:` and rejected a correct merge as soon as the lead committed during it; /code-review caught it (2026-10-19).
- **Check the merged tree equals the trial tree.** 2026-10-19: `git diff --name-only <trial> HEAD` empty after merging V8b+V3c proved main is exactly what ran 3× green.

## Lead tooling
- **macOS bash 3.2 does not fire an ERR trap for a failed subshell under `set -e`.** dispatch.sh left its worktree behind; use `cmd || undo` (2026-10-19).
- **Check a scratch test reached the step it tests.** Two of the 2026-10-19 tooling tests stopped early (a `//` in `$TMPDIR`, a wrong slug) and looked like passes or fails of the code. Resolve paths with `pwd -P`; print each case's outcome.
- **Hook output of 10,000 chars or more becomes a 2,000-char preview.** lead-context.sh builds the whole output and shortens its tail before that cap (2026-10-19).
- **A fresh lead reviewer still finds what the worker's own gates miss.** F7 2026-10-20: after the worker's second opinion, audit and /code-review, the lead's cold reviewer showed `tests/test_ci_workflow.py` passed a multi-line `run: |` step where `bash -e` runs past a failed `&&` link. Keep the per-branch fresh review even when the report lists many reviews.
- **Pushing main marks a draft PR "merged" when main gets its head commit.** PR #6 (2026-10-20) closed itself as merged on the owner's push of ae5dd0e. Close a CI-only draft PR before pushing main if it should read "closed".
- **Do not time a trial while another full suite runs on the Mac.** 2026-10-20: the F7 trial's third run took 202 s (vs 129 s) while the reviewer ran the suite. Run reviewer suites after the timed trial, or ignore times from overlapping runs.
- **`! VAR=1` alone sets nothing.** Each `!` command has its own shell; the owner writes `! AGENTFLY_ALLOW_PUSH=1 git push …` on one line (2026-10-20).
