# Docs verifier: lead-context.md §3 and §6.4 against the live Claude Code docs

Checked 15 Oct 2026 against the installed `claude --version` = **2.1.300**. The latest release is 2.1.301 (15 Oct), and nothing in it changes these claims. Pages were downloaded as raw `.md` from `https://code.claude.com/docs/en/<page>.md`; every URL below drops the `.md`. Base URL: `https://code.claude.com/docs/en/`. Verdicts: **CONFIRMED** / **CHANGED** (with what is true now) / **NOT FOUND**.

## Findings that change the plan (read first)
1. **CHANGED (§6.4 caveat is wrong): `.claude/settings.local.json` is shared with worktrees.** settings#keep-personal-settings-out-of-a-repository says: "In a worktree, it uses the file at the main checkout's root." worktrees#what-worktrees-share-with-the-main-checkout says the same about approvals ("applies in the main checkout and in every other worktree"), "whether you create the worktree with `--worktree` or with `git worktree add`". So a "lead-only" hook placed in settings.local.json **will also load in worker worktree sessions.**
2. **Untracked `.claude/commands`, `.claude/agents` and `.claude/skills` also read through to worktrees.** worktrees#what-worktrees-share: when the worktree has no `.claude/skills` directory, the main checkout's project skills load, and "The same read-through covers `.claude/agents` and `.claude/commands`." Untracked lead-only commands placed in the repo leak to workers.
3. **AGENTS.md is NOT loaded in this repo today.** CLAUDE.md exists, and `~/.claude/settings.json` sets `instructionFiles: "claude-md-or-agents-md"` (the default). Our CLAUDE.md says "Project rules live in AGENTS.md (read it first)" as plain text, which is not an `@` import. Claude only sees AGENTS.md if it chooses to Read it, and after compaction that read is summarized away. Fix: write `@AGENTS.md` in CLAUDE.md. The import then also pulls in SPEC.md (419 lines), because AGENTS.md line 6 has an un-backticked `Read @SPEC.md first`, and imports recurse.
4. **There is a documented opt-in lead persona.** `claude --agent lead`, with `.claude/agents/lead.md` holding frontmatter `hooks:` and an **empty body**, leaves the default system prompt unchanged and runs the agent's hooks alongside the settings hooks. Two more options: a shared SessionStart hook can check the input field `agent_type` (present only under `--agent`), or the lead can launch with `--settings lead.json`. Details in item 8.

## New or not in lead-context.md, useful for long memory
- **`claude --agent lead` with an empty-body agent + `initialPrompt`**: an opt-in lead persona that is resumable and keeps the default system prompt (sub-agents). Pair it with a `SessionStart` hook that checks `agent_type`.
- **`--settings lead.json`**: lead-only hooks, `autoMemoryDirectory`, `autoCompactWindow`, `idleCompaction` for one launch (settings#change-a-setting-for-one-session).
- **SessionStart `resume`/`fork` input** (v2.1.251+): `seconds_since_last_response`, `context_tokens`, `prompt_cache_likely_expired`, `estimated_cache_write_usd`, so a hook can warn before an expensive stale resume. SessionStart also fires on `clear`, so the same STATE re-injection can cover `/clear` (hooks#sessionstart).
- **`sessionTitle` hook output, `--name/-n`, `/rename`, `claude --resume <name>`**: name the lead session so it can be found again (cli-reference, hooks#sessionstart). `--fork-session` and `/branch` try a direction without polluting the lead.
- **`SessionEnd` hook** (`reason`: clear/resume/logout/prompt_input_exit/other): a place to dump state on exit. 2.1.300 fixed it sometimes not running when a background command was alive (changelog).
- **`PostCompact` `compact_summary`** to a log file; **PreCompact** can block auto/idle compaction while a critical step is in flight.
- **Status line `context_window.used_percentage`** (statusline): shows the context fill so the lead can be cleared well before 967K.
- **Subagent `autoCompactWindow`** (v2.1.296) and **`/reload-skills`** ("how to get skills back after compaction", changelog 2.1.299).
- **2.1.301**: switching to a smaller-context model now summarizes first with the previous model (relevant when moving the lead between models).
- **Switching tools**: AGENTS.md is the cross-tool file. Keep STATE/BOARD/DECISIONS in the repo (not in auto memory, which is Claude-only and repo-shared).
