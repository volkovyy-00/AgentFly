### What changed
- `agentfly/recorder/store.py`
  - `build_step_record` asks `rules.mark` itself: for read and shell steps `file_sensitive` is also true when `mark(payload, <this chat, unmarked>)` says the step touches a secret. No new stored field. The old `words()` check on the raw command is gone.
  - `StepRecord.command` is now always the cleaned command (`clean_command`); `hosts` and `file_path` come from it. New `StepRecord.raw_command` (not in repr or compare) carries the raw text only when `CLEAN_COMMANDS=0`; only the Neo4j Command node reads it.
- `agentfly/recorder/localstore.py`
  - `wipe_file` runs to one deadline (`WIPE_BUDGET_S = 10.0`, read at call time). Each blocking step gets the remaining time as `busy_timeout`. `_checkpoint` makes quick tries with a 0.2 s pause, so a waiting wipe does not hold the write lock against the recorder's writer. After the rows are deleted, any `sqlite3.Error` becomes `WipeIncomplete` ("rows deleted, but …; run it again", exit 1).
  - `purge_rows` ends with `_truncate_wal` (no waiting). When a reader blocks it, `LocalStore._wal_dirty` is set and `_tick` retries on every item and idle wake until it works.
- `app.py` is unchanged (see Deviations).

### Deviations and gaps
- **Deviation from the brief ("app.py: one value passed through").** `apply_mark`'s `marks` is true only on the event where the chat flips from unmarked to marked, counting a parent's mark. A subagent whose parent is already marked gets `marks=False` even when its own `bash -c 'cat .env'` marks it (probe: `stored.marked=True`, `marks=False`). Passing it would have left the bug open for subagents, so `store.py` calls the engine's own `mark()` instead and `app.py` is untouched. A side effect: a second secret read in an already-marked chat is still flagged `sensitive`.
- With `CLEAN_COMMANDS=0` the live trail now shows the cleaned command, and Neo4j's Host/File nodes derive from the cleaned text (only the Command node id keeps the raw text). README line ~185 says "saves raw commands"; outside this card, not edited.
- `agentfly/cli/wipe.py` (outside the touch list): when the delete itself cannot get the write lock, the CLI prints "failed (OperationalError); nothing else was changed". True but terse. Delete and VACUUM work time is not capped by the budget; it is small because the file is empty after the delete.
- `wipe` empties the history, and the "marked" flag is derived from steps. A chat marked before a wipe shows `marked=false` for steps saved after it, though sessions.json still blocks R1. Inherent to the V6 design.
- AGENTS.md "Command cleaning … CLEAN_COMMANDS=0 … secrets may reach Neo4j" is still correct.
