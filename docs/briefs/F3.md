# F3 · Install fixes from the V3a review: safe uninstall order, foreign entries, backups

You are a worker on card F3 in /Users/volkovyy/Projects/AgentFly/.claude/worktrees/ag-f3-install-fixes. Follow AGENTS.md and this brief; report per docs/reports/README.md. Never push; commit on branch ag-f3-install-fixes only, the lead merges.

**Summary.** An independent review of `agentfly init -g` / `uninstall` (2026-10-18) found that an interrupted or half-finished uninstall can leave Cursor denying every action, and that a few edge cases lose a backup or miss another tool's entry. Make uninstall and repair fail toward "AgentFly not running", never "Cursor blocked", and keep the user's backup.

**Written against:** 05ef3fc (2026-10-18).

**What was observed (2026-10-18, review probes on a temporary root)**
- Uninstall's one recursive delete of the AgentFly folder removed the hook client before the bundled Python. Interrupted at that point, the command Cursor still has cached (it reads hooks.json only at start-up) exited 2, which makes Cursor deny everything. A missing interpreter exits 127, which Cursor lets through.
- A foreign hooks.json entry that runs our client, written with escaped slashes (`\/`), survived uninstall while the folder was deleted. After uninstall no backup of hooks.json remained, and stripping our entries took no backup first.

**Scope**
- Uninstall, and the cleanup of a failed first install, first make the registered interpreter path vanish (for example by renaming the folder away), then delete. "Is this entry ours" is decided on parsed command strings; a hooks.json that cannot be parsed is checked as raw text for our path with plain or escaped slashes, and then uninstall refuses. Backups go next to hooks.json in Cursor's system folder (root-owned, timestamped) and survive uninstall; every rewrite of hooks.json takes one first. A failed restore keeps the old Python. An `OSError` during uninstall ends in a plain message and a non-zero exit, not a traceback. Install then uninstall returns another tool's hooks.json byte for byte. The two tests in References are made to catch the breakage they are named for.
- Touches: `agentfly/install/installer.py`, `agentfly/install/hooks_file.py`, `agentfly/cli/uninstall.py`, `tests/test_install_*.py`, README "Installation" if a message changes.
- Not included: the package-hash check before `sudo` (V3b), `start`/`stop`/`doctor` (V3b), the hook client and recorder.

**Acceptance criteria**
- An uninstall, or the cleanup of a failed first install, interrupted after any single delete or failing partway, leaves the registered command exiting 127 or 0, never 2 (test that interrupts at each step).
- A foreign entry that runs our client, with plain or escaped slashes, or an unparseable hooks.json naming our folder either way, makes uninstall refuse and change nothing.
- After install then uninstall, a backup of the original hooks.json still exists outside the removed folder, and each rewrite of hooks.json is preceded by one. Install then uninstall returns another tool's file byte for byte, including a file with no `hooks` key, an empty array and `{\n  }`.
- A restore that fails partway leaves the previous Python in place (test).
- An uninstall that hits a filesystem error prints a one-line reason and exits non-zero, with no traceback.
- The two tests named above fail when their behaviour is broken: swapping strip and delete, or removing our own archive-member check (every case); mutation results in the report.
