**Scope**
- Before the answer, on disk: every change that makes a chat stricter (mark, trigger, inherited window, parent link, the chat's parents changed by propagation) and every `links.json` change. Survive a recorder crash (KeepAlive restarts it); power loss is not in scope. The step counter and other fields are saved later; one writer, so an older snapshot never overwrites a newer one.
- Old notes go per D29, swept at start and hourly (as history's retention is); a note with no activity time yet (every note from before F11) counts as active from the first start after the upgrade.
- Touches: `agentfly/recorder/` (sessions, app, rules' `Session` for a last-activity time, localstore if the counter is recovered from history), `agentfly/cli/wipe.py` docstring if file names change, their tests (tests that read `sessions.json` right after a hook get an explicit flush), AGENTS.md "Testing", SPEC § 3 ("Where files live", "Local store") and § 5 "Scope of the mark" where they describe session notes.
- Not included: Neo4j retention or order gaps (D29 known gap); a forget-marks command; changing `_MAX_CALLS`; the hook client.

**Acceptance criteria**
- With 5000 stored chats, an action that changes no mark or link does not wait for a session-file write: its median hook time is within 5 ms of the 10-chat median, both measured interleaved in one `@wallclock` test so machine load hits both alike. With the session file unwritable, such an action still gets its normal answer.
- A recorder killed (SIGKILL) right after answering an action that marks a chat, fires a trigger, starts a Task, links a subagent or opens a chat inside an inherited window restarts with that chat, its parents and its subagents judged exactly as before (the next outbound send is blocked).
- After a SIGKILL or a clean stop (SIGTERM), a chat's next steps never reuse an order number already saved in history; after a clean stop nothing is lost.
- Per D29, a note idle 29 days or more is dropped unless kept (marked, a trigger, an open inherited window, or a parent of a kept chat, with its links); kept chats stay blocked after the sweep and a restart.
- A failed save of a mark or link gives the same answer as today (an error, so the client applies the offline guard), never a plain allow; a `sessions.json` from before F11, including the hackathon format, loads with every mark, and the first sweep after it drops no note.
- Every existing test passes and the demo replay's hook answers are byte-identical.
